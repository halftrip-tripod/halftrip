# 심사 계정 테스트 시나리오 (2026-08-20 규희)

> 목적: 플레이스토어 심사·공모전 심사 때 심사자가 어떤 화면을 열어도 "제대로 굴러가는" 상태를 보장.
> 각 계정에 **여행 4상태**를 미리 넣어두고, 아래 시나리오를 우리가 먼저 전부 눌러보고 제출한다.
> ⚠️ 심사 직전(W5~W6)에 여행 날짜를 심사 시점 기준으로 갱신해야 함 — 날짜가 지나면 상태가 밀린다.

## 2. 여행 4상태 시드 (계정당 4개)

| # | 상태 | 날짜 예시 (심사일 D 기준) | 지역 예시 |
| --- | --- | --- | --- |
| A | 여행 전 (신청 완료) | D+7 ~ D+8 | 접수중 지역 (2차 지역이면 최상) |
| B | 여행 중 | D-1 ~ D+1 | 완도 (가맹점·관광지 데이터 최다) |
| C | 여행 후 · 정산 신청 전 | D-4 ~ D-3 (정산 기한 안) | 강진 |
| D | 지난 여행 (정산 완료) | 1~2달 전 | 고창 — 고인돌 마그넷 도장 노출용 (가맹점 시드 최다, 관광지 시드는 1개뿐이라 완료 지역으로 적합) |

- C·D에는 인증샷·영수증·숙박확인서 증빙을 미리 채워둔다 (C는 게이지 일부만 채워 "제출 직전" 느낌, D는 완료 상태).
- 시드 방법: 운영 API 호출 스크립트 (로컬 로그인 → 여행 신청 → 증빙 업로드 → D는 정산 신청까지). Flyway로 유저 데이터 넣지 않는다.

## 3. 상태별 내 여행 탭 시나리오

**A. 여행 전**
- [ ] 여행 카드에 D-day·"여행 전" 상태 표기
- [ ] 상세: 지역 정보·환급 조건(50%·1인 10만) 표시
- [ ] 코스 추가 → 보관함에서 가져오기 ("보관함의 코스 중에서 골라서 등록해요") / 새로 생성
- [ ] 유튜브 코스 생성 (여행 연결) + 완료 알림 → 결과 화면 (DAY 토글·핀 포커스·정보창)
- [ ] 코스 수정·등록취소·코스함삭제 동작

**B. 여행 중**
- [ ] 인증샷 업로드 (지정 관광지 선택 → 사진 → 검증 결과)
- [ ] 영수증 OCR (금액·결제수단 인식, 지역화폐 결제 인정 확인)
- [ ] 숙박확인서 작성 (양식 렌더·전자서명·PDF 미리보기) — B 지역은 양식 있는 지역으로
- [ ] 가맹점 지도 (마커·대분류 칩·상세)
- [ ] 증빙 게이지가 최소 소비 금액 기준으로 차오르는지

**C. 여행 후 · 정산 전**
- [ ] 정산 신청 진입 → 제출 패키지(증빙 목록) 확인
- [ ] 부족한 증빙 안내 문구 정확한지 (결제수단·최소금액 안내가 지역 값과 일치)
- [ ] 정산 신청 제출 → 상태 전환
- [ ] 정산 기한 표기 ("여행 종료 다음날부터 N일 이내")

**D. 지난 여행**
- [ ] 후기 작성 → 인증 배지가 **해당 여행**을 가리키는지 (tripId 버그 재발 체크)
- [ ] 홈 지도에 다녀온 지역 도장 표시
- [ ] 지난 여행 상세 열람 (증빙·정산 내역 읽기 전용)

## 4. 그 외 탭 시나리오 (계정 공통)

**홈**
- [ ] 지도 핀 상태색 (접수중 파랑·오픈예정 연파랑·마감 회색) + 겹침 라벨 우선순위
- [ ] 다녀온 지역 도장 (D 여행 지역)
- [ ] 접수중/오픈예정 페인 카드 → 지역 상세 → 신청 URL 열림
- [ ] 저장 코스 카드: 최근 1개 + "N개 저장" → 보관함 이동
- [ ] 인기 코스 2개 (지역 무관 좋아요순) → 글 상세

**커뮤니티**
- [ ] 목록·필터 (지역/태그/인기순)
- [ ] 글 작성 (코스 첨부 포함) / 좋아요 / 댓글
- [ ] 지역 인기 코스 전용 피드 (코스 글만, 뒤로가기 복귀)

**스토어(온라인몰)**
- [ ] 지역 몰 목록 → 외부 링크 열림

**설정**
- [ ] 프로필·거주지 표시, 알림 설정, 로그아웃 → 재로그인

**공통 품질**
- [ ] 콜드 스타트(렌더 슬립) 시 로딩/재시도 UX — 심사자가 첫 진입에 503 보지 않게 심사 기간 keep-alive 고려 (하민)
- [ ] 푸시 알림 (유튜브 코스 완료) — FCM 운영 등록 후
