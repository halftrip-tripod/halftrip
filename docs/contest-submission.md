## 3. 제출 항목 (1차 심사)

### 3-1. 한국관광 콘텐츠랩 입력 항목

#### ① 팀 정보
- 팀명 — **확인만 가능, 변경 불가**
- 팀 구성원 정보 — **최종 팀원을 확정하여 입력** (팀대표 변경 불가)
- ⚠ 팀원 전원 사전에 투어라즈 회원가입 완료 필요
- ⚠ 1차 심사자료 제출 이후로는 팀원 포함 일체 수정 불가

#### ② 서비스 정보
- 서비스명 (1차 심사 전까지는 기능설명서에 반영하는 방식으로 변경 가능)
- 서비스 개요
- 서비스 유형 (웹 / 앱 / SW / 기타)
- **지역 특화 서비스 유무 및 특화 지역명** (가점 항목 — §4-2 참고)

#### ③ 서비스 테스트 정보
- **서비스 URL**
  - 앱(APP): **구글 스토어·애플 스토어·원스토어 중 최소 1개 스토어에 등록 완료된 링크** 제출
    - ⚠ 스토어 등록·승인 기간까지 고려하여 개발 완료 (**추가 기간 제공 없음**)
  - 웹(WEB): 접속 가능한 웹사이트 URL (별도 승인 절차 없음)
- **서비스 테스트 계정** — 3가지 로그인 방식 중 최소 1개 선택:
  - 로그인 불필요 → 계정 생성 불필요
  - SNS 연동 로그인(구글·카카오·네이버 등)만으로 이용 가능 → 계정 생성 불필요
  - 별도 계정 생성 로그인 → **테스트 전용 계정 생성 필수, 개인 계정 제출 불가.** 반드시 아래 지정 형식 중 하나:
    - 일반계정: `ID: openapi / PW: 2026openapi!`
    - 이메일 계정: `ID: openapi@메일도메인 / PW: 2026openapi!`
  - ⚠ 심사 시 서비스 로그인이 불가하면 **심사 제외** 가능

#### ④ 한국관광공사 OpenAPI 활용 정보
- 개발에 활용한 공사 OpenAPI **신청자별 인증키(인코딩키·디코딩키) 일체** 제출
  - 인증키를 통해 **개발 기간 내 API별 호출 건수** 및 서비스 내 활용 내역을 확인함
- (선택) 활용 API 중 대표 1개에 대해 운영계정 신청 여부 체크
- 활용한 공사 OpenAPI 목록
- 참고: [공공데이터포털 인증키 확인 및 운영계정 신청방법 매뉴얼](https://drive.google.com/file/d/1iAy4zLbWT4gWbc7PkW2mujdQBFD-2-BC/view?usp=sharing) (**사전 준비 필요, 필독**) *(8월에 링크 갱신됨)*

#### ⑤ 기능설명서 첨부

### 3-2. 기능설명서 (지정 양식, PDF 변환 제출)

- [양식 다운로드](https://drive.google.com/file/d/1mZ5t_w0Rx21QQ5JOQ5uBMgtn0laixkAF/view?usp=sharing)
- ⚠ **반드시 제공된 양식 사용.** 임의 양식 사용, 필수 항목 누락/변경 시 심사 제외 가능

| 목차 | 작성 내용 |

| 2. [선택] 지역 특화 서비스 구현 세부내용 | ① 특화 지역명(서울 제외) ② 구현 내용 |
| 3. 서비스 핵심 기능별 흐름도 | ① 핵심 기능명 및 설명(**최대 5개**) ② 기능 흐름도 |

- **파일 제한: PDF 1건, 10MB 이하.** 페이지 수 제한은 명시 없음 (양식 기본 9슬라이드 구성)
- 핵심 기능 흐름도 슬라이드는 기능당 1장, 필요 시 슬라이드 복사(Ctrl+D)로 추가 — 최대 5개 기능까지
- 선택 항목(지역특화·기타 데이터)은 해당 없으면 **슬라이드 삭제** / 가이드 문구·노란 박스는 작성 후 삭제
- OpenAPI 리스트 슬라이드는 5칸(API명+상세설명), 기타 데이터 슬라이드는 3칸
- 양식 zip 안에 PPTX(작성용) + PDF(참고용) 동봉 — PPTX로 작성 후 PDF 변환

### 3-3. 제출 화면 세부 (8/10 업로드 매뉴얼 기준)

- 제출 3단계: ① 개인정보 동의·유의사항 확인(팀 전원 확인 동의 포함) → ② 자료 입력 → ③ 제출 완료(등록 이메일로 확인 메일 발송)
- 앱 URL 입력 필드는 **안드로이드 앱스토어 URL / iOS 앱스토어 URL / 서비스 URL** 각각 존재
- **서비스 관련 기타 자료**: ZIP 1건, 50MB 이하 첨부 가능 (SW/기타 유형용이지만 필드 존재)
- **서비스 인증키: 최소 1건 ~ 최대 3건** 세트(인코딩키+디코딩키) 입력, 운영계정 전환 신청한 키 1건에 신청여부 체크
  - ⚠ data.go.kr `마이페이지 > Open API > 인증키 발급현황`에는 **인코딩키만** 보임 → 메인 마이페이지의 `개인 API 인증키`에서 인증키 복사(Encoding)/(Decoding) 버튼으로 둘 다 복사
- **활용 OpenAPI 서비스**: 체크박스 목록에서 실제 활용한 공사 API를 **모두** 선택 (1건 이상 필수, 미활용 시 심사 제외)
- 팀원 정보는 콘텐츠랩 회원가입 완료된 팀원만 회원 조회로 추가 가능
- 제출 기간 내 무제한 수정 가능(접수확인 → 심사자료 제출 버튼), 기간 종료 후 불가

## 6. 필수 준수 사항 (감점·탈락 리스크)

### 6-1. TourAPI(공사 OpenAPI) 활용 — 필수
- **OpenAPI 형태만 인정.** 파일데이터만 활용 시 심사 제외.
- **실시간 호출 방식 강력 권고.** 로컬 DB 저장/캐싱 시 개발 기간 내 호출 이력이 확인되지 않으면 불이익.
  - 부득이하게 로컬 DB 저장 방식이 필요하면 **별도 신청서** 작성 → tourapi@knto.or.kr 문의
- 제출한 인증키로 활용 API별 호출 건수 + 기능설명서의 활용 내역을 교차 검증함.

### 6-2. 출처 표기
- 서비스 내 데이터 출처 표기는 **필수**: `출처: ⓒ한국관광공사` 또는 `출처: ⓒ한국관광콘텐츠랩` (텍스트만 허용)
- 불가: `TourAPI` 단독 표기, 공사 공식 CI/BI 로고 이미지 사용
- 서비스명·로고에 "한국관광공사", "KTO" 등 공사 지칭 단어/로고 사용 금지 (공사가 직접 운영하는 것처럼 오인 유발 금지)

### 6-3. 위치기반서비스사업자 신고
- 이용자의 개인위치정보를 **사업자 서버로 전송**하면 신고 대상 (DB 저장 여부 무관, 전송 자체로 해당). 공모전 출품작·테스트 서비스도 동일 적용.
- 비신고: 위치정보를 단말기 내부에서만 활용하고 서버로 전송하지 않는 경우, 또는 익명/가명 처리로 개인 특정이 불가능한 경우.
- 판단이 애매하면 위치정보지원센터에 사전 검토 권장: https://www.lbsc.kr / 02-588-0185

### 6-4. 기타 유의사항
- 타 부문(생성형 AI 프롬프톤, 웹·앱 구현)과 **동일 서비스 중복 출품 불가** → 확인 시 심사 제외·시상 취소.
- 입력 항목·첨부파일 누락 시 심사 제외 가능.
- 서비스 유형을 두 종류 이상(웹+앱 등)으로 개발할 경우 반드시 동일 내용의 서비스여야 함.
- 허위 제출·결격 사유 확인 시 평가 제외, 수상 취소, 상금 회수.
- 서비스 소유권은 참가자에게 있으며 공사가 운영하지 않음. 초상권·저작권·표절 등 법적 문제는 지원자 책임.
- 개발 비용(도메인, 서버비 등) 지원 없음 → 클라우드 프리티어 활용 권장.
- 생성형 AI 기능 탑재, AI 코딩 도구(Cursor, Copilot 등) 사용 모두 **제한·감점 없음**. 평가 핵심은 안정적으로 구동되는 완제품.
- 서비스 형태(웹/앱)는 심사에 영향 없음. 단 앱은 스토어 승인까지가 실질 데드라인.
